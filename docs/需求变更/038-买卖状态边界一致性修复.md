# 买卖状态边界一致性修复

## 排查结果

- 生产数据库已经没有 Open 持仓，但候选池仍有 10 个 `bought` 候选；这些候选引用的买入信号均不存在。
- 旧逻辑只在缺失买入信号对应 Redis 实际持仓存在时恢复成交信息；两处都不存在时会永久保留 `bought`。
- 买入信号原先先发布、后保存候选状态，状态保存失败时可能留下已被交易模块消费但候选没有接管的持仓。
- 卖出成交后 Redis 删除失败只记录日志；服务重启会重新加载该残留，存在复活已关闭持仓的风险。

## 调整

- 买入信号改为先保存 `bought` 待确认状态，再发布到交易通道。
- 新增买入发布时间；10 秒内交易信号仍未落库且 Redis 没有真实持仓时，释放发射锁并恢复候选监控。
- 兼容旧候选：没有买入发布时间、信号不存在且没有 Redis 持仓时立即恢复。
- 买入发布失败时回滚候选状态并释放发射锁，同一根 K 线仍不会重复触发。
- 已关闭持仓市值低于 15k 时直接停止候选，不再短暂恢复为 `watching`；等于 15k 时可恢复监控。
- Redis 持仓删除失败进入持久化重试队列；服务启动时对 Redis 持仓读取数据库同一 position，数据库已关闭则删除残留且不载入运行时。

## 验证范围

- 买入状态在信号发布前已持久化。
- 新买入信号确认期内不会被提前恢复，超时后能够自动恢复。
- 历史缺失买入信号能够自动恢复。
- 已平仓低市值候选直接停止。
- Redis 删除短暂失败能够重试成功。
- 数据库已关闭的 Redis 残留不会在服务启动时复活。

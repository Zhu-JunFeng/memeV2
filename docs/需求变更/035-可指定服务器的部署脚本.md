# 可指定服务器的部署脚本

## 目标

新增统一部署脚本，默认部署到当前生产服务器，同时允许显式指定其他服务器、SSH 用户、端口、私钥、远端目录和 systemd 服务名。

## 使用方法

默认部署：

```bash
./scripts/deploy.sh
```

指定服务器：

```bash
./scripts/deploy.sh --host 10.0.0.8 --user admin
```

指定 SSH 端口和私钥：

```bash
./scripts/deploy.sh \
  --host example.com \
  --port 2222 \
  --identity ~/.ssh/prod
```

## 执行流程

1. 默认执行后端 `go test ./...`、`go vet ./...` 和前端测试。
2. 交叉编译 Linux AMD64 后端，并构建前端 `dist`。
3. 调用目标服务器公开 API 检查 `pending/submitted` 订单和 open position。
4. 上传到带 release 编号的临时文件和临时前端目录。
5. 在远端保留当前后端和前端备份，然后切换 release。
6. 重启指定 systemd 服务，验证本机后端和公网健康接口。

## 安全约束

- 默认目标为 `root@47.251.140.83`，远端目录为 `/data/solana-scalper-v2`。
- 目标服务器需要提前完成配置文件、数据库、Redis、Nginx 和 systemd 服务初始化；该脚本负责后续版本更新，不负责首次初始化。
- 后端默认交叉编译为 Linux AMD64；ARM64 服务器通过 `--goarch arm64` 指定。
- 脚本不会上传或覆盖远端 `config.yaml`、`.infra.env`、数据库、Redis 或日志。
- 脚本不保存 SSH 密码；未指定 `--identity` 时由 SSH 交互认证。
- 同一次部署复用 SSH 连接，使用密码认证时通常只需输入一次。
- 指定的 SSH 用户必须拥有远端目录写权限和对应 systemd 服务的管理权限。
- 默认检测到活跃订单或持仓就停止；只有显式传入 `--allow-active-trades` 才允许继续。
- `--skip-tests` 只用于已单独完成验证的发布，默认不跳过测试。

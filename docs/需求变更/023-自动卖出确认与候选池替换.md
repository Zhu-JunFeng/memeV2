# 自动卖出确认与候选池替换

## 背景

- 交易模式切换后，已有持仓的自动卖出必须继续使用持仓自身的模拟盘或实盘模式。
- 卖出信号发布不等于交易已成交，在订单失败、Redis 消息未被消费或持仓尚未关闭时，项目仍需保持 `bought` 监控。
- 候选池已满 50 个时，新的 50k-200k 优先项目需要能够替换较低优先级的 `watching` 项目。

## 修复

- 买入信号使用当前运行模式；自动卖出信号、订单和 Jupiter 执行统一使用持仓的 `tradeMode`。
- 候选状态新增 `sellSignalId` 和卖出发布时间。卖出发布后保持 `bought`，只有卖出信号已执行且数据库确认未平仓持仓已消失时，才恢复 `watching` 或停止低市值项目。
- 卖出信号为 `failed`、`rejected` 或 `skipped` 时，释放该信号的去重锁，保留原持仓并在后续轮询重试。
- Redis Pub/Sub 发布后 5 秒内查不到对应交易信号时，按消息未被消费处理，释放去重锁并重试。
- 每次卖出重试递增 attempt 并生成新的 signal ID，避免被交易服务的已消费信号去重逻辑跳过。
- 候选池已满时，新项目只能替换优先级更低的 `watching` 项目；`bought` 项目永远不参与替换。同优先级的新项目仍按池已满拒绝。

## 验证

- 覆盖当前为实盘、持仓为模拟盘时，自动卖出仍按模拟盘执行。
- 覆盖卖出发布后等待成交、成交后解除持仓监控、执行失败重试和消息未消费重试。
- 覆盖候选池已满时优先项目替换低优先级 `watching` 项目，并保留 `bought` 项目。

# 已平仓候选重复卖出信号修复

## 问题

- 候选买入成交后会把 `entryPriceSynced` 标记为 `true`。
- 持仓通过手动平仓关闭后，候选状态仍可能暂时保留为 `bought`。
- 旧逻辑只在首次同步实际买入市值时查询未平仓持仓；同步完成后不再检查持仓是否存在，导致旧卖出条件被反复命中。
- 交易模块将信号标记为 `skipped` 后，候选监控清除待确认信号并再次发布，形成重复 Telegram 通知。

## 调整

- 买入信号状态为 `executed` 时，每轮卖出判断前都查询对应未平仓持仓。
- PostgreSQL 暂时查不到时继续确认 Redis 运行时持仓，避免数据库异步落库期间误判已平仓。
- PostgreSQL 和 Redis 都不存在持仓时，清除旧买卖信号、入场信息、压力带和重试次数，并根据当前市值 rearm 或停止候选。
- rearm 时记录最后决策 K 线，禁止同一根 K 线立即重新买入。

## 验证

- 回归测试覆盖 `entryPriceSynced=true` 且持仓已关闭的候选，确认不会再次发布卖出信号。
- 保留 Redis 存在真实持仓时继续执行卖出判断的覆盖。

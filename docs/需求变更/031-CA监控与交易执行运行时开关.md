# 031-CA监控与交易执行运行时开关

## 需求

交易工作台新增两个可即时切换、重启后保持的配置：

1. 是否开启 CA 获取和监控。
2. 是否接收信号并执行交易，模拟盘和实盘共用同一开关。

## 实现

- 页面在“交易模式与执行看板”展示两个开关，关闭前弹出影响范围确认。
- `GET /api/trade/runtime` 同时返回 `caMonitoringEnabled` 和 `tradeExecutionEnabled`。
- `PUT /api/trade/runtime` 支持部分更新交易模式和两个开关，未传字段保持不变。
- 配置写入 `system_runtime_settings`，更新成功后同步到进程内原子状态并即时生效。
- 配置文件中的 `signal.candidate_monitor_enabled` 和 `trade.signal_consumer` 只作为数据库缺少对应配置时的首次默认值。

## 关闭行为

### 关闭 CA 获取和监控

- 停止 XXYY、GMGN 已毕业项目获取。
- 停止接收 Redis CA 消息。
- 停止扫描 `watching` 候选和检查 `bought` 候选的策略卖点。
- 保留候选池已有数据，重新开启后继续监控。
- 手动新增候选返回“CA 获取和监控已关闭”。

### 关闭接收信号并执行交易

- 信号判断和发布保持运行。
- Redis 自动交易消费者丢弃关闭期间收到的交易信号，不调用交易服务。
- 模拟盘、实盘都不再自动买入或卖出。
- 手动平仓等直接交易操作保持可用。

## 验证

- 单元测试覆盖首次默认值持久化、部分更新、数据库读写、候选新增门控、项目源调用门控和交易执行门控。
- 前端测试和构建通过后部署生产，验证接口返回、数据库配置键、服务状态和页面开关。

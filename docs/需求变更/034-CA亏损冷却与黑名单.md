# CA 亏损冷却与黑名单

## 需求

- 某个 CA 卖出成交亏损后，冷却 `1h`，冷却期间不能再次买入。
- 某个 CA 连续 `3` 次卖出成交亏损后，自动拉黑。
- 模拟盘和实盘使用相同逻辑。
- Candidates 列表支持手动拉黑；拉黑后立即停止监控、移出候选池，并禁止以后重新入池。

## 实现口径

- 连续亏损按 CA 全局统计，模拟盘和实盘的实际卖出成交共同组成一条连续序列。
- 实际实现盈亏小于 `0` 记为亏损：连续次数加一，并把 `cooldown_until` 更新为本次成交时间后 `1h`。
- 实际实现盈亏大于等于 `0` 视为非亏损：连续次数归零并清除冷却。
- 第 `3` 次连续亏损在卖出成交事务内自动设置 `is_blacklisted=true`，来源记为 `auto`。
- 手动拉黑来源记为 `manual`，写库后同步移除 Redis active candidate，并发送 Candidates SSE 删除事件。
- 冷却只拦截新买入，CA 仍可继续被监控；拉黑会停止候选监控。

## 防重复与多节点语义

- 连续亏损通过 PostgreSQL `UPSERT` 原子累加，不使用进程内计数。
- 所有候选入口，包括项目源、Redis 候选消息和页面手工添加，都会查询共享数据库黑名单。
- 候选扫描每轮再次检查黑名单，发现已拉黑 CA 后从 Redis active 池移除。
- 交易服务在 Jupiter 报价和执行前再次查询共享数据库，同时拦截冷却和黑名单，作为最终防线。

## 页面操作

- Candidates 操作列新增“拉黑”。
- 二次确认明确提示：拉黑后立即停止监控、移出候选池，且以后不能重新入池或买入。
- 操作成功后当前列表立即删除该 CA。
